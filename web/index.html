        How GitHub sign-in works

        A page cannot swap a GitHub code for a token: the exchange needs your OAuth app's secret, and GitHub's sign-in endpoint refuses browser calls. So one small relay holds the secret, and Chorus talks only to it.

        1. Create an OAuth App in your GitHub account and set its callback to this page's address.
        2. Deploy the relay, then set GITHUB_CLIENT_ID, GITHUB_CLIENT_SECRET and ALLOWED_ORIGIN.
        3. Paste the client ID and the relay address below, then press Sign in with GitHub.

        The secret stays in the relay, never here. And if you would rather not set this up, a personal access token uses the same connector.

        Chat privacy

        Community AI. Your message and relevant recent conversation are sent to AI Horde and its volunteer workers. Don’t share private information.

        On-device. Your model file and on-device messages aren’t sent to the community service, even if you switch connections later.

        Connectors. Keys you add for GitHub, Supabase or Cloudflare stay in this browser and are only sent to that service. They are never included in a message to a model.

        History. Chats are stored in this browser, not synced to an account. You can delete individual chats or clear them all in Settings. That doesn’t delete data already sent to a provider.
